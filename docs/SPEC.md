# 일본어 상용한자 학습 앱 제작 내역서

Nov 16, 2026 · @소리

## 1. 개요

일본어 상용한자 2,136자를 JLPT 급수 순서로 올라가며 익히는 개인용 학습 앱이다. 한자를 보고 스스로 아는지 판정하는 카드 방식을 뼈대로 하고, 한국어 한자 음훈을 일본어 읽기와 함께 익히는 것이 차별점이다.

### 확정된 요구사항

| 번호 | 내용 |
| --- | --- |
| R1 | 개인용. 계정, 서버, 광고, 결제 없음 |
| R2 | 학습 대상 : 일본 상용한자 2,136자 |
| R3 | JLPT 급수별(N5 → N1)로 나누고 단계별로 올라가는 구조 |
| R4 | 한자를 제시하고 사용자가 스스로 판정 : 복습 대상으로 둘지, 더 학습하지 않을지 선택 |
| R5 | 한국어 뜻을 보여줄 때 한국 한자 음훈(예 : 붙일 첩)을 함께 표시 |
| R6 | 추가 기능 12개를 전부 구현하고, 옵션에서 각각 켜고 끌 수 있게 함 |
| R7 | 디자인과 화면 구성은 공부할 맛이 나도록 공들임 |

### 이 문서에서 정한 전제

사용자가 정하지 않은 부분은 아래와 같이 정하고 문서 전체를 이 전제로 썼다. 바꾸려면 8장(기술 스택)만 고치면 되고, 기능·데이터·디자인 명세는 그대로 쓸 수 있다.

| 항목 | 전제 | 이유 |
| --- | --- | --- |
| 플랫폼 | 설치형 웹앱(PWA). 휴대폰 홈 화면에 설치해 앱처럼 실행, PC 브라우저에서도 동일하게 사용 | 획순 데이터가 SVG라 웹에서 바로 그릴 수 있고, 앱스토어 등록 없이 개인이 쓰기 쉬움 |
| 저장 위치 | 기기 안(IndexedDB). 백업 파일 내보내기·가져오기 제공 | R1(서버 없음) |
| 오프라인 | 최초 1회 접속 후 완전 오프라인 동작 | 이동 중 학습 |
| 화면 기준 | 세로 휴대폰 화면(폭 360\~430px) 우선, PC는 가운데 정렬 | 첨부한 참고 앱과 같은 사용 환경 |
| 인터페이스 언어 | 한국어 |  |

### 용어

| 용어 | 뜻 |
| --- | --- |
| 급수 | JLPT N5\~N1. 여기에 급수 표시가 없는 상용한자를 모은 '보충' 단계를 더해 6단계 |

## 2. 기능 명세

핵심 학습 흐름(2.1)은 항상 동작하고, 12개 추가 기능(2.2)은 옵션에서 각각 켜고 끈다. 기능을 꺼도 데이터는 지우지 않으며 다시 켜면 그대로 이어진다.

### 2.1 핵심 학습 흐름

1. 홈에서 \[오늘 학습 시작\]을 누르거나 단계 지도에서 장을 고른다.
2. 카드 앞면에 한자 한 글자가 크게 나온다.
3. 필요하면 \[한국어\] 또는 \[읽기\]를 눌러 해당 정보만 펼친다. 카드를 누르면 전부 펼친다. 펼치지 않고 바로 판정해도 된다.
4. 판정 버튼을 누른다.
   - 공부하겠음 : 복습 대상으로 남긴다.
   - 알고있음 : 다음 회독부터 나오지 않는다(F5가 켜져 있으면 간격을 늘려 재출제).
   - 알고있음 길게 누르기 : 즉시 졸업. 더 이상 출제하지 않는다.
5. 다음 카드로 넘어간다. 직전 판정은 \[되돌리기\]로 1회 취소할 수 있다.
6. 한 세션(기본 카드 20자)이 끝나면 결과 화면을 보여준다.
7. 장의 모든 한자가 '알고있음' 이상이 되면 장 완료, 급수의 모든 장이 완료되면 다음 급수가 열린다.

카드 한 장에 표시하는 정보의 전체 구성은 아래와 같다. 貼를 예로 든다.

| 영역 | 내용 | 예 | 관련 기능 |
| --- | --- | --- | --- |
| 앞면 | 한자 | 貼 | 핵심 |
| 한국어 | 한국 훈음 | 붙일 첩 | F1 |
| 한국어 | 정자체(일본 신자체와 다를 때만) | 国 ↔ 國 | F2 |
| 읽기 | 음독(가타카나) | チョウ | F1 |
| 읽기 | 훈독(히라가나, 오쿠리가나 구분) | は(る) | F1 |
| 힌트 | 한국 음과 일본 음독의 대응 | 첩(ㅂ받침) → チョウ(장음) | F3 |
| 묶음 | 같은 음부 한자 | 해당하는 한자만. 예 : 青 계열(セイ) 清·晴·精·静 | F4 |
| 비교 | 모양이 비슷한 한자 | 貼 / 賠 | F8 |

### 2.3 기능별 세부 규칙

**F1 한일 음훈 병기**

- 한국 훈음은 대표 훈음 1개를 크게, 나머지 훈음은 작게 표시한다.
- 일본에서 만든 한자(국자)는 '일본 고유 한자' 표지를 붙이고 뜻 풀이를 표시한다. 한국 자전에 훈음이 있는 국자(峠 고개 상, 畑 밭 전 등)는 표지와 함께 훈음도 표시한다. 훈음도 뜻 풀이도 없으면 표지만 표시한다. 국자 판정은 `overrides/ko_hunum.csv`의 '일본 고유 한자' 열로만 한다(검수 목록 `review/kokuji_review.csv`).
- 뜻 풀이(`meaning_ko`)는 선택 항목이다. 있으면 한국 훈음 아래에 표시하고, 비어 있으면 카드에 한국 훈음만 표시한다.
- 음독·훈독이 여러 개면 해당 급수에서 쓰이는 읽기를 앞에 두고, 나머지는 흐리게 표시한다. 단 급수별 읽기 출처가 확정되기 전까지는 모든 읽기를 KANJIDIC2 순서대로 같은 굵기로 표시한다(M4, 9장 확인 항목).
- F1을 끄면 한국어 줄은 뜻 풀이(없으면 대표 훈음) 하나, 읽기는 음독 / 훈독을 한 줄로 색 없이 표시한다.

**F3 음 대응 규칙 힌트**

- 규칙은 별도 표(3장의 `sound_rules`)로 관리하고 한자마다 해당 규칙 번호를 연결한다.
- 초기 규칙 목록(검수 대상) : ㄱ받침 → ク·キ, ㄹ받침 → ツ·チ, ㅂ받침 → 장음(ウ), ㅇ받침 → 장음(ウ·イ), ㄴ·ㅁ받침 → ン, 초성 ㅎ → カ행, 초성 ㅂ·ㅍ → ハ행.
- 규칙에 맞지 않는 한자에는 힌트를 표시하지 않는다.
- 판정 : 한국 음은 검수 반영 뒤의 대표 음(`ko_main.eum`) 하나로, 음독은 여러 개 중 하나라도 맞으면 해당한다. '행' 규칙은 탁음 행을 함께 적는다(초성 ㅎ → カ·ガ행, 초성 ㅂ·ㅍ → ハ·バ·パ행). 'ㅇ받침 → 장음'은 음독이 ウ·イ로 끝날 때만 해당한다. 일본 고유 한자에는 규칙을 붙이지 않는다.
- 힌트 줄에는 규칙 이름과 "첩 → チョウ"처럼 규칙에 맞는 음독을 함께 표시한다.

**F6 3단계 자기평가**

- 버튼 순서는 왼쪽부터 공부하겠음, 애매함, 알고있음.
- 애매함은 같은 세션 안에서 한 번 더 나오고(세션의 맨 뒤, 한 한자당 한 번), F5가 켜져 있으면 짧은 간격으로 편성된다.

**F7 역방향 출제**

- 출제 유형 : (가) 한국 훈음 → 한자, (나) 히라가나 읽기 → 한자. 옵션에서 유형과 비율(기본 30%)을 고른다.
- 정방향에서 '알고있음'을 1회 이상 받은 한자만 역방향 대상이 된다.
- 답 확인은 카드를 눌러 한자를 펼친 뒤 자기 판정한다. F10이 켜져 있으면 캔버스에 직접 써본 뒤 펼칠 수 있다.
- 출제 위치 : 세션의 정방향 카드 수 F에 대해 역방향 R장(R / (F + R) ≈ 비율, 최소 1장)을 정방향 사이에 고르게 끼운다. 정방향 분량이 끝나도 남은 역방향 카드를 마저 낸다. [공부하겠음만 다시]와 고른 한자 학습에서는 내지 않는다.
- 후보 : 장 학습이면 그 장의 한자를 먼저, 그다음 다른 장에서 익힌 한자. 간격 반복(F5 켬)은 역방향 카드가 새 카드이거나 오늘 출제일인 것(출제일이 지난 것 먼저), 회독(F5 끔)은 역방향에서 아직 '알고있음'을 받지 않은 것(학습 중 먼저).
- 앞면 글 : 한국 훈음은 대표 훈음, 히라가나는 훈독(오쿠리가나는 괄호) 최대 3개, 훈독이 없으면 음독을 히라가나로. 고른 유형을 낼 수 없는 한자(예 : 한국 훈음 없음)는 다른 유형으로 낸다.
- 역방향 판정은 장 진행·회독에 반영하지 않고, 같은 세션 안에서 다시 내지 않는다. 결과 화면의 [공부하겠음만 다시]에는 정방향 카드만 넣는다. 격자 색과 통계는 정방향 기록으로 계산한다.
- 써 보기 칸 : 펼치기 전에는 빈 칸(지우기 버튼), 펼치면 쓴 획 위에 본보기를 겹쳐 보인다. 채점은 하지 않는다.
- 한자 한 자의 학습 상태 초기화(S5)는 역방향 카드도 지운다.

**F9 대표 단어**

- 단어마다 단어(일본어), 읽기, 한국어 뜻을 표시하고, F11이 켜져 있으면 발음 버튼을 붙인다. 표시 개수는 `words_count`.
- 한국어 뜻이 번역 초안이면 '미검수' 표지를 붙인다. 검수된 값(`overrides/words_ko.csv`)이 있으면 표지를 뗀다.
- 두 글자 이상 한자 단어는 한국 한자음을 함께 적는다(첫 글자 두음법칙 적용, 女子 → 여자). 뜻에 같은 말이 이미 있거나(외국 → 외국), 가나가 섞였거나, 한국 음이 없는 한자가 있으면 적지 않는다.
- 학습 카드에서는 전부 펼쳤을 때만 보인다(F3·F4·F8과 같음).

**F10 획순 및 따라 쓰기**

- 애니메이션 : 한 획씩 그리며 재생, 속도 3단계, 획 번호 표시 선택.
- 따라 쓰기 : 흐린 본보기 위에 손가락으로 쓰고, \[본보기 숨김\]으로 빈 칸에 쓰기도 가능. 1차 구현은 채점 없이 본보기와 겹쳐 보여주는 방식, 획 판정은 후속 과제로 둔다.
- 따라 쓰기 시트의 버튼 : \[한 획 지우기\], \[지우기\], \[본보기 숨김\]/\[본보기 보기\]. 쓴 획 수를 'n / 전체획'으로 보여준다. 쓴 선은 시트를 닫으면 사라진다.
- 애니메이션은 획 길이에 비례한 시간으로 그리고 획 사이에 잠깐 쉰다. 칸을 누르거나 \[다시 재생\]으로 다시 그린다.

**F11 발음 음성**

- 읽는 글 : 음독은 가타카나 그대로, 훈독은 오쿠리가나 점과 접사 표시(-)를 지운 히라가나, 단어는 읽기(히라가나). 음독 → 훈독 순서로 읽고 같은 소리는 한 번만 읽는다.
- 자동 재생(`tts_auto`)은 카드에서 읽기 줄이 펼쳐질 때 한 번 읽는다. 카드를 넘기면 읽던 것을 멈춘다.

- 기기에 설치된 일본어 음성으로 읽는다. 일본어 음성이 없는 기기에서는 버튼을 숨기고 옵션 화면에 안내를 표시한다.

**F12 학습 통계**

- 지표 : 급수별 진도율, 장별 회독 수, 일별 학습 시간과 카드 수, 연속 학습일, 판정 비율, 자주 틀리는 한자 상위 30개.

### 2.4 공통 기능

- 검색 : 한자, 한국 음(첩), 한국 훈(붙이다), 일본어 읽기(はる, チョウ)로 찾기.
  - 다른 자형 입력 : 상용한자표 자형과 다른 코드로 입력해도 찾아야 한다. 叱·剥·填·頬을 입력하면 𠮟·剝·塡·頰이 나온다(Unihan kJoyoKanji의 JIS X 0208 대체 자형). 승인된 한국 정자체(`ko_form`, 예 : 國)로 입력해도 해당 신자체(国)가 나온다. 대응표는 빌드가 `meta.json`의 `aliases`로 내보낸다.
- 한자 격자 : 2,136자를 한 화면 격자로 보고 상태별 색으로 진행 상황 확인.
- 즐겨찾기 : 한자에 표시해 따로 모아 학습.
- 백업 : 학습 기록 전체를 파일 하나로 내보내고 가져오기.

| `similar` | 문자 배열 | 유사 한자 |  |
| `words` | 문자 배열 | 대표 단어 id 2\~3개 |  |

`words.json` : `{id, text, reading, meaning_ko, reviewed, level, kanji[]}`. `meaning_ko`는 검수한 뜻(`overrides/words_ko.csv`)이 있으면 그것, 없으면 번역 초안(`drafts/words_ko_draft.csv`), 둘 다 없으면 null. `reviewed`가 거짓이면 화면에 '미검수' 표시를 붙인다. 단어의 한국 한자음(学生 → 학생, 첫 글자에 두음법칙 적용)은 앱이 한자별 대표 음으로 계산한다

`phonetic_groups.json` : `{id, component, reading, members[]}`

`strokes/<코드포인트>.json` : KanjiVG에서 뽑은 획 경로 배열. 한자 상세를 열 때만 읽는다.

### 3.4 빌드 파이프라인과 검수

Python 스크립트로 원본을 내려받아 합치고, 사람이 고친 내용은 덮어쓰기 파일로 분리해 다시 빌드해도 사라지지 않게 한다.

1. `fetch.py` : 원본 내려받기(KANJIDIC2, kanji-data, hanja.txt, KanjiVG, JMdict). 버전과 내려받은 날짜를 `SOURCES.lock`에 기록.
2. `build_kanji.py` : 상용한자 2,136자 추리기, 급수·장·순번 부여.
3. `build_korean.py` : 한국 훈음 연결. 순서는 (가) 한자 그대로 hanja.txt 조회, (나) 없으면 정자체 후보로 바꿔 조회(결과는 검수 목록에 올림), (다) 둘 다 없으면 KANJIDIC2의 한국 음만 넣고 검수 목록에 올림. 정자체 후보는 Unihan으로 만들고 '일치 / 엇갈림 / 후보 없음'으로 나눠 `review/ko_form_review.csv`에 낸다. `kanji.json`의 `ko_form`은 `overrides/ko_form.csv`에서 승인된 값만 쓴다.
4. `build_words.py` : 한자마다 해당 급수 이하 단어 2\~3개 선정. 단어 속 한자가 모두 그 한자와 같거나 더 쉬운 급수(N5 → N1 → 보충 순)이고, JMdict 사용 빈도 표시(news1·ichi1·spec1·spec2·gai1)가 있는 단어를 우선한다. 고어·희귀·불규칙 표기는 뺀다. 뜻 검수 목록 `review/words_ko_review.csv`(영어 뜻, 초안, 검수 여부)를 낸다.
5. `build_relations.py` : 음 대응 규칙 정의, 음부 묶음, 유사 한자 계산. 음부와 유사 한자는 KanjiVG가 제공하는 구성 요소 정보를 이용해 공통 부품으로 계산한다.
   - 음부 묶음 : 가장 바깥쪽 `kvg:phon` 구성 요소가 같고, 같은 음독을 공유하는 상용한자 2자 이상. 음부 자체가 상용한자면 함께 넣는다(青 → 清·晴·精…).
   - 유사 한자 : 구성 요소 집합의 겹침(Jaccard 0.35 이상), 바깥쪽 부품 공유, 획수 차 4 이하로 점수를 매겨 최대 3자. 자동 계산이며 예시를 빌드 보고서에 싣는다.
   - 음 대응 규칙 : 규칙 정의는 `overrides/sound_rules.csv`가 있으면 그것을, 없으면 2.3의 초안을 쓴다. 한자별 판정은 7단계에서 검수 반영 뒤 대표 음으로 하고, 규칙별 해당 한자 수와 예시를 `review/sound_rules_review.csv`로 낸다.
6. `build_strokes.py` : KanjiVG SVG에서 획 경로 추출.
7. `apply_overrides.py` : `overrides/*.csv` 반영, 5단계 결과를 합쳐 `kanji.json`, `sound_rules.json`, `phonetic_groups.json` 출력.
8. `validate.py` : 2,136자 전수 검사(필수 필드 누락, 중복, 급수 합계) 후 보고서 출력.

검수가 필요한 항목은 아래 네 가지다. 빌드가 검수용 CSV를 만들고, 고친 내용을 `overrides/`에 저장한다.

| 항목 | 검수가 필요한 이유 | 검수 파일 |
| --- | --- | --- |
| 대표 훈음 | hanja.txt에 훈음이 여러 개인 한자가 있어 대표 1개를 골라야 함 | `ko_hunum.csv` |
| 신자체 ↔ 정자체 대응표 | 검증된 공개 대응표를 이번 조사에서 확정하지 못함. 빌드 때 후보를 만들고 확인 | `ko_form.csv` |
| 단어의 한국어 뜻 | 공개 사전에 한국어 뜻이 없어 JMdict 영어 뜻을 옮긴 번역 초안(`drafts/words_ko_draft.csv`)을 쓴다. 초안은 '미검수' 표시와 함께 앱에 보이고, 검수한 행은 표시를 뗀다 | `words_ko.csv` |
| 음 대응 규칙표 | 이 문서의 초기 규칙 목록은 초안 | `sound_rules.csv` |

## 4. 복습 알고리즘

판정 버튼은 같고, F5(간격 반복)를 켜느냐에 따라 다음에 언제 다시 나오는지가 달라진다. 두 방식은 같은 `cards` 테이블을 쓰므로 도중에 전환해도 기록이 이어진다.

### 4.1 회독 방식 (F5 끔)

첨부한 참고 앱과 같은 구조다.

| 판정 | 결과 |
| --- | --- |
| 공부하겠음 | 이번 회독의 남은 목록에 유지. 다음 회독에 다시 출제 |
| 애매함 (F6) | 같은 세션 뒤쪽에 한 번 더 출제. 다음 회독에도 출제 |
| 알고있음 | `status = review`. 다음 회독부터 제외 |
| 알고있음 길게 누르기 | `status = graduated`. 어디서도 출제하지 않음 |

- 한 장의 남은 한자를 끝까지 돌면 회독 수가 1 올라가고, 남은 한자만으로 다음 회독을 시작한다.
- 남은 한자가 0이 되면 장 완료.
- 화면 상단 표시 형식 : `N4 · 4장 · 1회독 · 12/20`.

### 4.2 간격 반복 방식 (F5 켬)

스케줄 계산은 FSRS 알고리즘의 TypeScript 구현인 ts-fsrs에 맡긴다. 판정을 ts-fsrs의 평가 등급에 아래처럼 연결한다.

| 판정 | ts-fsrs 등급 | 체감 동작 |
| --- | --- | --- |
| 공부하겠음 | `Rating.Again` | 같은 세션 안에서 다시 나온 뒤 짧은 간격으로 편성 |
| 애매함 (F6) | `Rating.Hard` | 간격이 조금만 늘어남 |
| 알고있음 | `Rating.Good` | 그날 다시 나오지 않고 바로 일 단위 간격. 새 카드와 다시 배우는 카드도 같음 |
| 알고있음 길게 누르기 | 사용 안 함 | `status = graduated`로 바꾸고 출제 대상에서 제외 |

- 세션 구성 순서 : (1) 오늘 출제일이 된 복습 카드, (2) 새 한자. 새 한자는 열려 있고 완료하지 않은 장에서 장 순서·순번대로 고른다. 세션 안에서 보여주는 순서는 각 묶음 안에서 `card_order`를 따른다.
- '오늘 출제일' : 출제일이 오늘 안(기기 시간대 자정 전)인 카드. 회독 방식에서 판정해 출제일이 없는 카드는 F5를 켠 직후 바로 복습 대상이 되고, 하루 복습 상한 안에서 조금씩 들어온다.
- 공부하겠음은 같은 세션 안에서 3장 뒤에 다시 나온다.
- 단계 지도에서 장을 골라 들어오면 그 장의 복습과 새 한자를 낸다. 이때는 하루 새 한자 수를 적용하지 않는다(미리 하기).
- 같은 날 다시 나오는 규칙 : 공부하겠음과 애매함만 그날 다시 나온다. 알고있음은 그날 다시 나오지 않는다.
  - ts-fsrs 설정 : `learning_steps = ['1m']`(기본값 `['1m', '10m']`에서 단계를 하나로 줄임), `relearning_steps`는 기본값 `['10m']`.
  - 새 카드·학습 중인 카드 : 공부하겠음 1분, 애매함 1.5분(단계 1분 × 1.5) 뒤로 편성되고 Learning에 머문다. 알고있음은 학습 단계를 다 마친 것으로 처리되어 바로 Review(일 단위)로 간다.
  - 복습 카드 : 공부하겠음이면 Relearning으로 10분 뒤, 그 뒤 알고있음이면 다시 일 단위.
  - 같은 세션 안에서 다시 내는 것은 세션 목록이 따로 처리한다 : 공부하겠음은 3장 뒤, 애매함은 세션 맨 뒤에 한 번.
- 하루 새 한자 수(기본 20)와 하루 복습 상한(기본 100)을 옵션으로 둔다.
- 목표 기억률(기본 90%)을 옵션으로 두고 ts-fsrs의 `request_retention`에 전달한다.
- 장 완료 기준 : 장의 모든 한자가 '알고있음'을 1회 이상 받았거나 졸업 상태.
- 회독 수는 이 방식에서도 유지한다 : 장의 한자를 모두 한 번씩 본 시점마다 1 증가.

### 4.3 공통 규칙

- 되돌리기 : 직전 판정 1건만. `review_logs`의 마지막 기록을 지우고 카드 상태를 판정 전 값으로 복원한다. 복원을 위해 판정 직전의 카드 상태를 메모리에 보관한다.
- 순서 : 기본은 장 안에서 섞어서 출제. 옵션으로 순번대로 출제 가능.
- 역방향 카드(F7)는 정방향과 별도의 `cards` 행(`direction = reverse`)으로 스케줄한다.
- 단계 잠금 : 기본은 앞 장을 완료해야 다음 장이 열린다. 옵션으로 잠금을 풀면 어느 장이든 바로 학습할 수 있다. 이미 판정한 한자가 들어 있는 장은 잠금과 상관없이 열려 있다.
- 장 완료 판단 : 장 진행 기록의 완료 표시, 또는 한자별 학습 상태로 장의 모든 한자가 '알고있음'을 1회 이상 받았거나 졸업한 경우.
- 시간 측정 : 카드가 화면에 뜨 순간부터 판정까지를 `elapsed_ms`로 기록. 60초를 넘으면 60초로 자른다(자리 비움 보정).

## 5. 디자인 시스템

디자인 콘셉트는 '먹과 종이'다. 따뜻한 종이색 바탕 위에 먹색 한자를 크게 놓고, 주홍색 도장 하나를 강조색으로 쓴다. 한자 자체가 화면의 주인공이 되고, 익힌 한자가 격자에 채워지는 것이 눈에 보이게 하는 것이 목표다.

### 5.2 설계 원칙

1. 한자가 주인공 : 카드 화면에서 한자는 화면 높이의 4분의 1 이상을 차지한다. 나머지 요소는 그보다 항상 약하게 보인다.
2. 엄지 한 손 조작 : 판정 버튼과 주 버튼은 화면 아래 3분의 1에 둔다. 버튼 높이 56px 이상.
3. 한 번에 하나씩 펼침 : 답 영역은 한국어, 읽기, 더 보기 순으로 접혀 있고 필요한 만큼만 펼친다.
4. 색에 역할 고정 : 음독·훈독·한국 음훈의 색, 판정 3종의 색을 앱 전체에서 동일하게 쓴다. 색만으로 구분하지 않고 항상 글자 라벨을 함께 둔다.
5. 진도가 눈에 보임 : 익힌 한자는 격자 칸이 채워지고, 장을 완료하면 도장이 찍힌다.
6. 움직임은 짧게 : 모든 전환 300ms 이하. 장식용 애니메이션은 장 완료와 세션 결과에만 쓴다.

### S2 단계 지도

급수를 위에서 아래로 N5 → N1 → 보충 순으로 놓고, 각 급수 안에 장을 칸으로 나열한다.

- 급수 머리글 : 급수 이름, 글자 수, 진도 막대.
- 장 칸(한 줄에 4칸) : 장 번호, 회독 수, 완료한 장에는 주홍 도장. 잠긴 장은 흐리게 표시하고 자물쇠 아이콘.
- 장을 누르면 아래에서 시트가 올라온다 : 그 장의 한자 20자 미리보기(상태색 포함), \[이 장 학습\], \[처음부터 다시\].
- 현재 학습 중인 장은 테두리를 `--shu`로 강조하고 화면 진입 시 그 위치로 스크롤한다.

- 역방향 카드(F7)의 앞면은 한국 훈음 또는 히라가나를 48px로 표시하고, 카드 상단에 '한자 떠올리기' 라벨을 붙인다.
- 답 영역이 카드 높이를 넘으면 카드 안에서 스크롤한다. 판정 버튼은 항상 화면 아래에 고정한다.
- 스와이프 : 카드 폭의 30%(최대 120px)를 넘기거나, 그 절반 이상을 빠르게 튕기면 판정한다. 모자라면 제자리로 돌아오고 카드 펼치기로도 처리하지 않는다. 답이 카드 높이를 넘쳐 스크롤이 생긴 부분에서는 세로 끌기가 스크롤이 된다(위쪽 판정은 그 밖에서). 역방향 카드는 한자를 펼친 뒤에만 스와이프로 판정한다.
- 효과음(`sound_fx`)은 오디오 파일 없이 기기에서 짧은 음을 만들어 낸다(판정 3종, 졸업, 장 완료).
- 💡 힌트(F3), 같은 음부(F4), 닮은 한자(F8)는 전부 펼쳤을 때(카드 누르기)만 표시한다. 닮은 한자는 접힌 한 줄로 시작하고, 공부하겠음을 2회 이상 받은 한자는 `similar_auto_open`이 켜져 있으면 펼친 채로 시작한다.
- 카드에서 한자 칩이나 \[상세 보기\]를 누르면 S5를 카드 위에 겹쳐 연다. 세션을 떠나지 않으므로 닫으면 같은 카드로 돌아온다.

### S4 세션 결과

- 상단 : 이번 세션 한자 수, 걸린 시간.
- 가운데 : 판정 3종의 비율을 한 줄 막대로 표시하고, 아래에 이번 세션 한자를 상태색 칸으로 나열. 칸을 누르면 S5.
- 장을 완료했으면 도장 애니메이션과 '4장 완료' 문구.
- 하단 버튼 : \[공부하겠음만 다시\], \[계속하기\], \[홈으로\].

### S5 한자 상세

위에서 아래로 다음 구역을 순서대로 놓는다. 꺼진 기능의 구역은 표시하지 않는다. 단 F1을 끄면 음훈 구역 대신 학습 카드의 F1 끔과 같은 읽기·뜻 한 구역을 놓는다(읽기를 볼 곳이 없어지지 않도록).

1. 머리 : 한자 120px, 급수·획수·학습 상태 칩, 즐겨찾기, 발음 버튼.
2. 음훈(F1) : 한국 훈음 전체, 음독 전체, 훈독 전체.
3. 정자체 대조(F2) : 신자체와 정자체를 같은 크기로 나란히 놓고 각각 '일본', '한국' 라벨.
4. 음 대응(F3) : 규칙 설명 한 문장과 같은 규칙의 한자 가로 스크롤 목록.
5. 획순(F10) : 애니메이션 칸과 \[따라 쓰기\] 버튼. 따라 쓰기는 전체 화면 시트로 열린다.
6. 대표 단어(F9) : 단어, 읽기, 뜻, 발음 버튼.
7. 같은 음부(F4), 닮은 한자(F8) : 칩 목록. 누르면 해당 한자 상세로 이동.
8. 내 기록 : 판정 이력(최근 10회를 점으로), 다음 복습일, \[학습 상태 초기화\].

### S6 한자 격자

2,136자를 원고지처럼 한 화면 격자로 보여주는, 이 앱의 대표 화면이다.

- 한 줄 8칸, 급수별 구획 머리글. 칸 배경을 5.3의 상태색으로 칠한다.
- 상단 필터 칩 : 전체 / 학습 중 / 애매 / 알고있음 / 졸업 / 즐겨찾기.
- 칸을 누르면 S5. 두 손가락으로 줄이면 한 줄 16칸의 전체 보기(글자 없이 색만)로 전환.
- 렌더링은 화면에 보이는 줄만 그리는 방식으로 한다.
- 칸 상태는 정방향 카드 기준이다. '애매'는 학습 중이면서 마지막 판정이 애매함인 한자, '알고있음'은 '알고있음'을 1회 이상 받은 한자(장 완료 기준과 같음)다. 역방향(F7) 성적은 칸 색에 넣지 않는다.
- 머리글의 격자 버튼으로도 전체 보기를 켜고 끈다(두 손가락을 쓸 수 없는 기기). 필터 칩 아래에 상태별 색과 한자 수를 보인다.
- 상세 화면에 다녀오면 보던 자리·필터·보기를 유지한다.

### S7 통계

- 요약 카드 4개 : 연속 학습일, 누적 학습 시간, 알고있음 이상 한자 수, 오늘 학습량.
- 달력 : 최근 12주의 일별 학습량을 색 농도로 표시.
- 급수별 진도 : 급수마다 상태 비율 누적 막대 1줄.
- 일별 추이 : 최근 30일의 판정 수 막대.
- 자주 틀리는 한자 : 공부하겠음 횟수 상위 30자. \[이 한자만 학습\] 버튼.
- 달력 농도는 하루 목표(`daily_goal`) 대비 5단계(없음 / 절반 미만 / 목표 미만 / 1.5배 미만 / 그 이상)로 칠한다.
- 일별 추이 아래에 지금까지의 판정 비율(공부하겠음 / 애매함 / 알고있음, 졸업은 알고있음에 포함)을 적는다.
- \[이 한자만 학습\]은 회독 진행과 별도의 세션이며, 판정은 지금의 복습 방식(F5)으로 기록한다.

### S8 설정

7장 참조.

### S9 검색

- 입력창 하나. 한자, 한국 음, 한국 훈, 가나 모두 같은 창에서 찾는다.
- 결과 행 : 한자 · 한국 훈음 · 음독 · 급수 · 상태색 점. 누르면 S5.
- 찾는 방법 : 한국 음은 같은 음, 한국 훈은 기본형으로 입력해도 찾는다(붙이다 → 붙일, 맑다 → 맑을). 가나는 히라가나·가타카나를 구분하지 않고 훈독의 점을 무시하며, 앞부분만 입력해도 찾는다. 한자는 `aliases`로 다른 자형을 바꿔 찾는다. 완전 일치를 앞에, 같은 정도 안에서는 급수·순번 순서로 최대 100자.

### 빈 상태와 예외 화면

| 상황 | 표시 |
| --- | --- |
| 최초 실행 | 안내 3장(판정 방법, 스와이프, 옵션 위치) 후 N5 1장부터 시작. 이미 아는 급수가 있으면 시작 급수를 고를 수 있음 |
| 오늘 할 것이 없음 | 홈에 '오늘 분량 완료' 도장과 \[다음 장 미리 하기\] |
| 데이터 불러오기 실패 | 원인 한 줄과 \[다시 시도\] |
| 일본어 음성 없음 | 발음 버튼 숨김, 설정의 발음 항목에 안내 문구 |

- 최초 실행 기록은 기능 설정(7장)이 아니므로 settings 테이블에 `onboarding_done`, `start_level` 키로 따로 둔다. 이 기능 전부터 학습 기록이 있던 기기는 안내를 건너뛴다.
- 시작 급수는 N5~N1 중에서 고른다. 앞 급수의 모든 장을 완료(`completed_at`)로 기록해 시작 급수 1장을 연다. 한자별 학습 상태는 바꾸지 않으며, 건너뛴 장도 열려 있어 언제든 학습할 수 있다. 장 크기를 바꿔도 건너뛴 급수는 완료로 남고, 전체 초기화하면 건너뛴 기록도 지운다.

## 8. 기술 스택과 프로젝트 구조

앱은 TypeScript로 만드는 설치형 웹앱이고, 데이터 빌드는 Python으로 한다.

| 구분 | 선택 | 역할 |
| --- | --- | --- |
| 언어 | TypeScript | 앱 코드 |
| 화면 | React + Vite | 화면 구성과 빌드 |
| 스타일 | CSS 변수 + CSS Modules | 5장의 토큰을 CSS 변수로 그대로 정의 |
| 움직임 | Pointer Events + Web Animations API(브라우저 내장) | 카드 스와이프, 판정 시 카드 나가기. 움직임이 카드 한 장의 끌기·나가기뿐이라 라이브러리 없이 구현한다(M7에서 Motion 대신 결정) |
| 기기 DB | Dexie(IndexedDB) | 3.3의 사용자 데이터 |
| 복습 스케줄 | ts-fsrs | 4.2의 간격 계산. Node.js 20 이상 필요 |
| 설치·오프라인 | vite-plugin-pwa (2.0, MIT. Workbox 7.4) | 홈 화면 설치, 오프라인 캐시. 첫 접속 때 앱·woff2 글꼴·한자 데이터·획순 전부(약 24MB, 2,861개 파일)를 미리 받아 둔다. 새 버전은 자동 적용하지 않고 화면 위쪽에 "새 버전이 있습니다 \[새로 고침\]"을 띄운다. 아이콘은 scripts/make_icons.py로 Klee One의 '漢'을 주홍 도장 모양으로 그린다 |
| 발음 | Web Speech API(브라우저 내장) | 일본어 음성 읽기 |
| 획순 | SVG 직접 렌더링 | KanjiVG 경로를 한 획씩 그림 |
| 테스트 | Vitest | 스케줄·회독 규칙 단위 테스트 |
| 데이터 빌드 | Python 3.11 이상 | 3.4의 파이프라인 |
| 배포 | 정적 호스팅(GitHub Pages 등) 또는 PC에서 로컬 실행 | 휴대폰 설치에는 https 주소가 필요 |

```
│  ├─ build_relations.py  build_strokes.py  apply_overrides.py  validate.py
│  ├─ raw/                 # 내려받은 원본 (git 제외)
│  ├─ overrides/           # 검수 결과 CSV (git 포함)
│  └─ SOURCES.lock
├─ public/
│  ├─ data/                # 빌드 결과 JSON, strokes/
│  └─ fonts/
└─ src/
   ├─ styles/tokens.css    # 5장 토큰
   ├─ db/                  # Dexie 스키마, 백업
   ├─ domain/              # scheduler.ts(회독·SRS), session.ts, progress.ts
   ├─ content/             # JSON 로더, 검색 색인
   ├─ settings/            # 옵션 정의와 기본값 (7장 표와 1:1)
   ├─ screens/             # Today, Levels, Study, Result, Detail, Grid, Stats, Settings, Search
   └─ components/          # KanjiCard, RevealRow, GradeButtons, StrokePlayer, WritingPad, Stamp …
```

설계 규칙 :

- `domain/`은 화면 코드를 모르는 순수 함수로 작성하고 단위 테스트를 붙인다.
- 12개 기능은 `settings/`의 값 하나로 켜고 끈다. 화면은 그 값을 읽어 해당 구역을 그리거나 건너뛴다.
- 콘텐츠 JSON은 앱 시작 시 `kanji.json`만 읽고, 단어·획순은 필요할 때 읽는다.

## 9. 개발 단계

8단계로 나누고, 각 단계가 끝날 때마다 휴대폰에서 실제로 써볼 수 있는 상태가 되게 한다. M2가 끝나면 참고 앱과 같은 수준의 학습이 가능하다.

| 단계 | 작업 | 완료 기준 |
| --- | --- | --- |
| M0 뼈대 | 프로젝트 생성, `tokens.css`, 글꼴 포함, 하단 탭과 빈 화면 9개, 라이트·다크 테마 | 휴대폰 브라우저에서 탭 이동과 테마 전환이 됨 |
| M1 데이터 | 파이프라인 1\~3, 7\~8단계. N5로 먼저 검증 후 전체 | `validate.py`가 2,136자 통과 보고, 검수용 CSV 생성 |
| M2 핵심 학습 | S2, S3(앞면·펼치기·판정 2단계), 회독 방식, S4, 기기 DB 저장, 되돌리기 | N5 1장을 여러 회독 돌려 장 완료까지 가고, 앱을 껐다 켜도 이어짐 |
| M3 옵션과 간격 반복 | S8 전체, F5, F6, S1 | 12개 스위치가 모두 저장되고, F5·F6을 켜고 끌 때 카드 동작이 4장대로 바뀜. 스케줄 단위 테스트 통과 |
| M4 한국어 지식 기능 | F1, F2, F3, F4, F8, 파이프라인 5단계, S5, S9 | 国·学·貼·清·働(국자) 5자에서 각 구역이 명세대로 표시됨 |
| M5 단어·소리·쓰기 | F9(파이프라인 4단계), F11, F10(파이프라인 6단계) | 단어 표시, 발음 재생, 획순 재생, 따라 쓰기가 동작 |
| M6 진도 화면 | S6, S7(F12), F7 | 2,136칸 격자가 끊김 없이 스크롤되고 상태색이 맞음. 역방향 카드 출제 |
| M7 마감 | 5.6의 움직임·진동, 빈 상태 화면, 백업·복원, 설치형 웹앱 설정, 출처 표시 | 홈 화면에 설치 후 비행기 모드에서 전 기능 동작. 백업 파일로 다른 브라우저에 복원됨 |

검수 작업(3.4의 CSV 4종)은 M1 이후 개발과 나란히 진행할 수 있다. 검수 전에도 앱은 자동 생성값으로 동작한다.

### 확인이 필요한 항목

- [x] 신자체 ↔ 정자체 대응표 : 직접 대응표는 공개 출처가 없음(M1 확인). Unihan으로 후보를 만들고 검수한다. M1 결과 일치 157자, 엇갈림 221자, 후보 없음 1,758자.
- [x] kanji-data, ts-fsrs, JMdict 어휘 목록의 라이선스 문구를 저장소에서 직접 확인한다. (kanji-data : MIT 확인, M1. ts-fsrs 6.0.0 : MIT, 함께 설치되는 @open-spaced-repetition/srs-kit 1.0.0 : BSD-3-Clause 확인, M3. JMdict : EDRDG 라이선스 CC BY-SA 4.0, 출처 표시 필수 확인, M5)
- [x] hanja.txt 훈음 : 한자 그대로 1,849자, 정자체 후보로 214자, 없음 73자 (M1 빌드 보고서).
- [x] 급수별 글자 수 : N5 79, N4 166, N3 367, N2 367, N1 985, 보충 172 (M1 빌드 보고서).
- [ ] 상용한자표 인정 읽기 : KANJIDIC2에 표시가 없어 F1의 '해당 급수 읽기 우선'에 쓸 출처가 필요하다. M4 조사 후보 : KEINOS gist(위키백과 상용한자표 기반), cjkvi-tables, melissaboiko/joyodb, sph-mn/kanji, kanjiapi.dev. 모두 라이선스를 확정하지 못해 아직 쓰지 않는다. 확정 전까지 모든 읽기를 같은 굵기로 표시한다.
- [ ] 음 대응 규칙 7개(2.3 초안)의 검수 : `review/sound_rules_review.csv`. 고칠 때 `overrides/sound_rules.csv`.
- [ ] 유사 한자 자동 계산 결과의 검수 : 지금은 덮어쓰기 파일 없음. 필요하면 `overrides/similar.csv`를 추가한다.
- [x] 한국어 뜻 풀이(`meaning_ko`) : 선택 항목으로 확정. 공개 출처가 없어 `overrides/ko_hunum.csv`로만 채우고, 비어 있으면 카드에 훈음만 표시한다.
- [ ] 사용할 휴대폰에 일본어 음성이 설치되어 있는지 확인한다. (M5 : 음성이 없으면 발음 버튼을 숨기고 설정 F11 항목에 안내가 나오는 것까지 확인. 실제 휴대폰 확인은 사용자)
- [ ] 대표 단어가 3개보다 적은 한자 5자(岬·且·朕·摯·憬) : JMdict 조건(같은 급수 이하 한자, 흔한 단어 우선)으로는 더 찾지 못했다. 필요하면 `overrides/words.csv`를 추가해 직접 고른다.
- [ ] 단어 한국어 뜻 초안의 검수 : `review/words_ko_review.csv`. 고칠 때 `overrides/words_ko.csv`. 검수 전 초안은 '미검수' 표시로 앱에 보인다.

## 10. Claude Code 인계 지침

이 문서를 Markdown으로 내보내 프로젝트 폴더의 `docs/SPEC.md`로 저장하고, 아래 두 파일 내용을 그대로 쓰면 이어서 제작할 수 있다.

### `CLAUDE.md`에 넣을 내용

```markdown
# 프로젝트 규칙

- 명세는 docs/SPEC.md가 기준이다. 명세와 다르게 구현해야 하면 먼저 이유를 말하고 확인을 받는다.
- 개발은 SPEC 9장의 M0~M7 순서로 한다. 한 단계의 완료 기준을 확인한 뒤 다음 단계로 간다.
- 각 단계를 시작할 때 무엇을 왜 만드는지, 어떤 도구를 쓰는지 먼저 설명한다.
- 색·글꼴·간격은 src/styles/tokens.css의 변수만 쓴다. 컴포넌트에 색 값을 직접 쓰지 않는다.
- 일본 한자를 표시하는 요소에는 lang="ja", 한국 정자체에는 lang="ko"를 지정한다.
- 12개 기능(F1~F12)은 src/settings의 값으로만 켜고 끈다. 키 이름은 SPEC 7장 표와 같게 한다.
- src/domain은 화면 코드에 의존하지 않는 순수 함수로 쓰고 Vitest 테스트를 함께 작성한다.
- data-pipeline/overrides의 CSV는 사람이 검수한 결과다. 스크립트로 덮어쓰지 않는다.
- 외부 데이터를 내려받을 때는 출처 주소, 버전, 라이선스를 SOURCES.lock에 기록한다.
- 확인되지 않은 데이터는 추측으로 채우지 않고 검수 목록에 올린다.
- 예외 : 사전 뜻을 옮긴 번역 초안(예 : 단어의 한국어 뜻)은 미검수 표시를 붙여 앱에 사용할 수 있다. 초안은 data-pipeline/drafts에 두고, 사람이 검수한 값(overrides)이 있으면 그것을 쓰고 표시를 뗀다.
- 인터페이스 문구는 한국어로 쓴다.
```

### 첫 지시문

```text
docs/SPEC.md를 끝까지 읽고, 9장의 M0부터 시작해줘.
시작하기 전에 M0에서 만들 파일 목록과 설치할 패키지를 먼저 보여주고,
내가 확인하면 진행해줘. M0가 끝나면 휴대폰에서 확인하는 방법을 알려줘.
```

### 단계별 지시문 형식

```text
SPEC 9장의 M<번호>를 진행해줘. 끝나면 완료 기준을 하나씩 확인한 결과를 보여줘.
```
